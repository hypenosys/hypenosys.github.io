Guía de HYPENOSYS Search

Cómo utilizar el buscador, qué hace realmente y qué garantías de seguridad no deben darse por supuestas.

Uso · Arquitectura · BYOK · Seguridad · Limitaciones · Desarrollo

Uso básico

  1. Introduce una pregunta o términos de búsqueda.
  2. La aplicación consulta resultados de SearXNG.
  3. En modo privado, puede generar un AI Overview mediante un modelo de Ollama.
  4. Deep Research intenta ampliar las búsquedas y leer un número limitado de páginas públicas.
  5. Abre siempre las fuentes antes de confiar en información importante.

Una pregunta de seguimiento puede usar el contexto reciente, pero las fuentes y numeración corresponden a cada respuesta.

Arquitectura

Navegador
  │
  ├── Search público / BYOK ── FastAPI ── SearXNG
  │                                 └── API externa del proveedor
  │
  └── Search privado ──────── FastAPI ── SearXNG
                                    └── Ollama (acceso interno restringido)

El modo privado tiene autenticación y un despliegue separado. La seguridad de la red interna depende además de cortafuegos, permisos de la tailnet y configuración del host.

Componentes principales: Python/FastAPI, Docker Compose, SearXNG, Ollama y modelos locales compatibles. El frontend usa HTML, CSS y JavaScript.

Claves propias (BYOK)

La interfaz contempla OpenRouter, OpenAI, Anthropic, Gemini, Groq, Mistral, DeepSeek, xAI, Together, Fireworks, Cerebras, NVIDIA NIM y Perplexity API. La compatibilidad real de modelos y formatos debe comprobarse proveedor por proveedor.

Nunca introduzcas claves BYOK por HTTP. Antes de habilitar usuarios públicos hacen falta HTTPS, límites de peticiones, protección de claves, mensajes de error seguros y una revisión del flujo completo.

Principios de seguridad

  • No exponer Ollama directamente a Internet.
  • Restringir acceso privado con autenticación del backend y reglas de red; Tailscale por sí solo no autoriza a todos los usuarios.
  • Tratar páginas recuperadas como datos no confiables: pueden contener instrucciones maliciosas (prompt injection).
  • Limitar tamaño, redirecciones, destinos y tiempo de lectura de URLs para reducir SSRF y consumo excesivo.
  • No registrar ni publicar tokens, claves, credenciales, IP de administración o configuraciones privadas.
  • Aplicar caché y límites de búsqueda para evitar bloquear motores de terceros.

Limitaciones conocidas

  • Los motores SearXNG pueden devolver cero resultados por límites, CAPTCHAs o fallos temporales.
  • La reformulación actual contiene ajustes experimentales; no es un planificador general de consultas.
  • Las citas enlazan a resultados, pero no verifican por sí solas cada afirmación.
  • La longitud del contexto y el presupuesto de generación pueden truncar investigaciones largas.
  • El historial conversacional no se almacena como memoria persistente del producto.

Estado y colaboración

Esta guía refleja el prototipo que se está probando, no una release pública auditada. Las próximas tareas son mejorar recuperación multifuente, validar citas, incorporar pruebas de integración y preparar un despliegue HTTPS seguro.

El código desplegado vive actualmente en un entorno de pruebas autoalojado. No existe aún en esta página un repositorio de código fuente público y verificado de HYPENOSYS Search.
